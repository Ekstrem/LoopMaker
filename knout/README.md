# Кнут (knout) — детектор простоя ролей

«Кнут» смотрит на outbox'ы ролей проекта и, если **80% ролей простаивают**
(не писали дольше порога), пишет пинг в чат координатору `@TL`, чтобы тот
разморозил работу. Это не гейт и не «правило» — это сигнал: «петля встала,
нужен человек/координатор».

## Решил так (не плагин DSH, а функция)

Это **инструмент** (как `sweep.py`/`health.py`), а не плагин доставки чата
(`dsh-loopmaker`): он не общается с DSH-сессиями, а просто пишет строку в чат.
Плагином он не может быть: DSH не будит тред по расписанию, а Кнуту нужен
внешний планировщик (cron / GitHub Actions `schedule`).

## Конфиг (loop.config.json, секция `knout`)

```json
"knout": {
  "project": "XDiary",       // имя проекта (метка в сообщении)
  "idle_hours": 6,           // роль «простаивает», если не писала дольше
  "idle_ratio": 0.8,         // доля простаивающих (0.8 = 80%)
  "interval_min": 15,        // период (справочно; cron ставит сам)
  "chat_dir": "5-tech-backlog/chat",
  "roles": ["be","do","fe","te","ar","po","lm"],
  "from_chat": "5-tech-backlog/chat/lm.md",
  "to": "@TL"
}
```

Все поля необязательны — есть defaults в `knout.py`. TL в подсчёт не входит
(он адресат пинга, а не «работающая» роль).

## Запуск

```bash
python knout.py --config loop.config.json            # один прогон
python knout.py --config loop.config.json --dry-run  # показать, не писать
python knout.py --selftest                           # самопроверка
```

Периодичность (15 мин) — на стороне планировщика: cron или workflow
`knout.yml` с `schedule: - cron: '*/15 * * * *'`. Сам скрипт — один прогон.

## Канон и копия

Источник правды — здесь (`LoopMaker/knout/knout.py`). Проектная копия —
`<проект>/tools/knout.py`. Правка — в обоих местах (как у остальных
инструментов, см. `LoopMaker/RULES.md` §10).
