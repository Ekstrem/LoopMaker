# PDR — шаблон решения о процессе петли (v2)

> **Назначение:** решение о **процессе** (как работаем), а не о продукте/архитектуре.
> Лимит: **одна страница**. Вариантов — **2–3**, обязательно включая «ничего не менять».
> **Если решение дешевле, чем его оформление — это не PDR, а строка в чате** (или черновик `D-xx`).
> Полный канон ADR-подхода — `templates/adr.md`; здесь облегчённая редакция (процесс меняется чаще).

```markdown
# PDR-NN. {короткое название решения}

| Поле | Значение |
|---|---|
| **Статус** | обсуждается / принято / отклонено / заменено |
| **Владелец решения** | @роль — чья это зона |
| **Заменяет** | PDR-XX (если пересмотр), иначе — |
| **Дата** | 2026-11-09 |
| **Пересмотр** | когда и по какому событию пересматриваем |

## Контекст

Что произошло и **какая цифра/инцидент** заставили это обсуждать (ссылка на коммит/прогон/сообщение).
Без цифры — это не проблема, а мнение.

## Варианты

| Вариант | Плюсы | Минусы | Цена |
|---|---|---|---|
| **A. {имя}** | | | |
| **B. {имя}** (рекомендую) | | | |
| **C. ничего не менять** | | | |

Плюсы/минусы — **исчерпывающие** (не по одному пункту); цена — не только часы, но и рост CI,
риск дефекта, стоимость поддержки.

## Решение

**Вариант {X}** — обоснование в 1–2 строки.

### Протокол (по ролям, не «все согласны»)

| Роль | Принял | Возразил / условие | Воздержался |
|---|---|---|---|
| @роль | ✅ 2026-11-09 | | |

**Бюджет комментариев:** не больше 2 на вариант от роли; после бюджета без консенсуса решение
принимает владелец зоны.

### Обязательства

| Что | Ответственный | Как проверяется |
|---|---|---|
| {задача / гейт / метрика} | @роль | {команда / строка дашборда} |

Решение без обязательства и проверки — **не решение, а совет** (правило §18).

### Комплаенс

| Что | Значение |
|---|---|
| Где источник правды | {файл/репо: что считается нормой после принятия} |
| Когда пересматриваем | {дата или триггер} |
| Кто проверяет | @роль |
| Что делаем при расхождении | {гейт красный / задача / откат} |
```

---

## Как переводить черновик в PDR

1. Идея пожила в `retro/drafts/` (D-xx) и получила **цифру** или инцидент.
2. Заполняешь PDR по шаблону, собираешь позиции **тех, кого затронет** (не всех ролей).
3. Владелец зоны ставит `принято`, обязательства уходят в задачи.
4. Старые PDR не переписываем: если решение меняется — новый PDR с полем **«Заменяет»**.
