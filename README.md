# LoopMaker

Инструменты и правила для **петли** — замкнутого цикла работы агентов через git:
задача-file → роль-агент → outbox-чат → верификация координатором → закрытие владельцем.
Без ручной пересылки сообщений между тредами.

Проверено на проекте XDiary: 6 ролей, 40 задач, два бэклога, чат без merge-конфликтов
по конструкции (один писатель на файл).

## Плагин: чат → сессия (оживление ролей)

`dsh-loopmaker` — плагин DSH: следит за outbox-чатом, находит сообщение, адресованное
роли, и доставляет его в сессию этой роли. Тред просыпается сам — переключаться вручную
не нужно.

```
be.md:  - [10:00] → @FE: посмотри контракт JWT
                ↓  (плагин, poll 5 с)
сессия «XDairy | FrontEnd»  ←  сообщение от BackEnd: «посмотри контракт JWT»
```

Установка, настройка (`chatDir`, `project`, `roles`, `sessions`), диагностика —
в **[PLUGIN.md](PLUGIN.md)**.

## С чего начать

1. **[AGENTS.md](AGENTS.md)** — правила петли и чеклист запуска в новом проекте (§8).
2. **[loop.config.json](loop.config.json)** — единственный файл, который правится под проект:
   зоны ролей, папка бэклога, статусы, порядок папок задач.
3. **[templates/](templates/)** — что вставить в свой репозиторий: формат задачи,
   мини-`AGENTS.md` для папки-зоны, шаблон проектного `AGENTS.md`, workflow'ы
   (`sweep.yml` — часовой обход, `guard-secrets.yml` — утечки, `chat-guards.yml` —
   лёгкие guard'ы на переписку).
4. **[tools/](tools/)** — девять скриптов, работающих от конфига:
   - `check_paths.py` — guard: роль не вышла за свою папку (по префиксу коммита);
   - `stats.py` — таблица статусов задач в README (`--write` / `--check`);
   - `merge_chat.py` — сводка диалога из outbox-файлов;
   - `chat_inbox.py` — гейт координатора: есть ли вопрос без ответа;
   - `chat_lint.py` — линтер формата строки чата (пишет автору в `chat/_lint.md`);
   - `check_secrets.py` — секреты и их **фрагменты** в чате/задачах/доках (код 1 на находке);
   - `keycmp.py` — сравнить два секрета, не печатая значения;
   - `check_workflow_paths.py` — guard: у тяжёлых workflow есть фильтр путей (чат не гоняет CI);
   - `sweep.py` — обход петли: задачи без движения и «обещано, но не начато».

## Быстрый старт

```bash
python tools/check_paths.py --zones      # карта зон из loop.config.json
python tools/check_paths.py --range HEAD~20..HEAD --report-only   # аудит истории
python tools/stats.py --write            # обновить таблицу в README
python tools/merge_chat.py               # собрать сводку чата
python tools/chat_inbox.py               # вопросы к @TL без ответа (код 1 = есть)
python tools/chat_lint.py                # формат строк чата (код 1 = есть нарушения)
python tools/check_secrets.py            # утечки секретов (код 1 = есть находки)
python tools/check_workflow_paths.py     # фильтры путей у workflow (код 1 = есть нарушения)
python tools/ci_metrics.py --workflow-path ci-tests.yml   # p50/p95 джобов CI
python tools/sweep.py --config loop.config.json   # обход: что стоит без движения
```

## Принципы (коротко)

- Один тред агента = одна роль; у роли одна своя папка + своя папка задач и свой outbox.
- Задача = файл с ID, критериями приёмки и статусом из фиксированного набора.
- Координатор верифицирует, **закрывает владелец** задачи.
- Чат — outbox-модель: свой файл только для записи, все файлы для чтения.
- Правила живут в `AGENTS.md` (в корне и в каждой зоне) — их читает каждый агент.
- Сгенерированное (сводка чата, таблица статусов) не правится руками.
