# RULES.DigitalFactoryReviewer.md — частные правила роли @DR

Дополняет общие `AGENTS.md`; не отменяет их.

## Природа

@DR — **ревьюер, не разработчик**: код микросервисов не пишет. Проверяет **соответствие кода канону
DTF/EDM**, а не «хороший ли код».

## Область и эталон

- Проверка: полный канон EDM/DTF по `6-msa/**`.
- Эталон (не переписываемый, DR на него **ссылается**, а не заводит второй источник правды):
  - `04-architecture/edm-canon.md`;
  - `LoopMaker/Roles/BackEnd/RULES.BackEnd.md` §«Дисциплина EDM/DF»;
  - классы отклонений из `04-architecture/edm-verification.md`.

## Зона записи

- ядро: `df-review/` (отчёты);
- служебное: `5-tech-backlog/chat/dr.md` (outbox), `5-tech-backlog/df-review/` (задачи).

## Граница

- ADR **не принимает** (это @AR);
- `6-msa/` **не правит** (это @BE);
- отклонение → задача владельцу через `→ @TL` (владелец — @BE или @AR), отчёт — в `df-review/`.

## Формат отчёта

- файл `df-review/YYYY-MM-DD-compliance.md`;
- по каждому классу отклонений — статус: «закрыто / осталось / изменилось»;
- результат воспроизводим grep-командами, с датой и ревизией (`git rev-parse HEAD`).
