# KB-002: «12 часов без релиза при зелёном коде» — доставка встала целиком (2026-11-19/20)

## Метаданные

- **Дата инцидента:** 2026-11-19 00:13 → 2026-11-20 18:08 (простой ~42 ч с перерывами)
- **Статус:** решено — транспорт снова синкает, защита от реверта в коде, токен для PR найден (ждёт обновления секрета)
- **Роль:** @LM (+ @DO по workflow, @TL по доставке)
- **Проект:** XDiary + LoopMaker (плагин `dsh-loopmaker`)

## Симптом

«Всё встало» при зелёном коде: PR не мержатся, чат не синкает, кнут/статистика молчат,
lock не доезжает, прод без свежего образа. Итог по сводке TL: **14 классов дефектов за сутки,
все в механике доставки, ни одного в коде продукта**; 78 прогонов, 56 failure.

## Корневые причины (по порядку вскрытия)

1. **`enforce_admins: true` (владелец) заблокировал ВСЕ прямые пуши.** Бот (`commitChat`
   `HEAD:main`), lock-sync, whip, review-whip, stats, health — все пушили напрямую и все
   умерли молча (`protected branch hook declined`). Кнут «работал» (детектил простой), но
   пинг не доходил.
2. **`[skip ci]` в бот-PR глушил required-чеки.** Заголовок/коммит `chat(bot): sync [skip ci]`
   и lock-sync `[skip ci]` → workflows не запускаются → `5 of 5 expected` → PR висит вечно.
3. **Токен для PR в облаке отсутствовал.** `PROJECT_PAT` (Secrets) — fine-grained только под
   Issues (`issues: write`); `PROJECT_PAT_ISSUE` — невалиден (401). Рабочий `ghp_…` (классич.,
   `repo`-скоуп) и fine-grained с `pull_requests: write` лежали **локально** (`GHT.md`), а не
   в Secrets — workflow их не видели.
4. **Stale seen-снимок → порча данных.** После ребута плагин перезагружал устаревшее
   состояние; `fetch` глотал ошибку молча, union брал stale `origin/main` (2205 против 2248)
   и **ревертил файл на 43 сообщения назад** (физическая потеря).

## Действия (что было сделано)

1. `commitChat` переведён на **ветка + PR + merge** (вместо прямого push).
2. `[skip ci]` убран из чат-PR и lock-PR (артефактные PR — всегда с чеками, D-23).
3. 4 workflow (`whip`/`review-whip`/`stats`/`health`) переведены на ветка+PR.
4. `fetch` сделан **жёстким** (не обновил origin/main → коммит пропущен).
5. union — защита `merged >= origin` (никогда не ревертить).
6. raw-эскалация больше не рендерится pointer-шаблоном (убраны фантомные «в tl.md от LoopMaker»).
7. Тесты: `[skip ci]`, `mergeChatLines` (dedup/маркеры/порядок), raw-эскалация — 76/76.

## Ошибки и уроки

1. **Не проверил цепочку целиком до «готово».** Сказал «нужен ребут», а токен для PR не
   проверил — оказалось «нужен ещё и токен». Нарушил свой же §12 «прогресс = артефакт»:
   не выдавай «готово» раньше, чем пройдена вся цепочка (кто пишет → чем пушит → чем PR →
   чем мержит → кто читает).
2. **Инкрементальные фиксы плагина = серия ребутов.** Пять раз дёргал владельца на ребут,
   хотя мог собрать все правки `lib/*.js` в один батч. Теперь норма: плагин — одним коммитом.
3. **Токен в Secrets ≠ токен в `GHT.md`.** Два независимых набора; «добавил скоуп» в одном
   не меняет другой. Надо проверять скоупы фактом (`gh api user --include` → `X-Oauth-Scopes`),
   а не по памяти.
4. **`[skip ci]` в PR ≠ экономия, а блокировка мержа.** Документировано: `skip ci` только
   там, где мерж не нужен гейтом; артефактные PR — всегда с чеками (D-23).

## Закрыто после разбора (2026-11-25)

- `PROJECT_PAT` обновлён без раскрытия значения. Сквозное доказательство: `health.yml`
  (run `45639606344`) создал PR `#3399`, который затем был смержен. Значение секрета
  не проверялось и не печаталось — только метаданные и факт создания PR.
- Канон адресатов утверждён владельцем: `@EX` — владелец, `@all` — все роли, кроме
  автора. `chat_lint --selftest` = 11/11, node-тесты = 78/78, текущий `check-chat` = rc=0.
  `broadcast: true` записан в источник и активный конфиг; действующее поле перечитывается
  только при запуске плагина, поэтому фактическая рассылка `@all` ждёт следующий ребут DSH.

## Открытые вопросы

- После следующего ребута DSH проверить фактическую доставку `@all` всем ролям, кроме автора.
- Пост-ребутная зачистка `tl.md` (BEL + дедуп + адресаты) применена TL и держится.
