# Knowledge Base — петля XDiary / LoopMaker

Записи о реальных инцидентах: симптом → диагноз → корневые причины → действия → уроки.

Цель: чтобы следующий похожий случай чинился за минуты, а не за часы. Каждая запись
обязана отделять **факт** (проверено) от **гипотезы** (предположение) — иначе KB
становится источником новых ошибок, а не защитой от них.

## Формат записи

- Метаданные (дата, статус, роль, проект).
- Симптом.
- Корневые причины (проверенные, каждая отдельно).
- Действия.
- Ошибки и уроки.
- Открытые вопросы.
