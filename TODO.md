## TODO-1: правило против утечки секретов в петле (после инцидента в XDiary)

**Статус:** открыт
**Дата:** 2026-11-04
**Источник:** инцидент в XDiary, 2026-11-03

### Что случилось
В XDiary роль **BackEnd** вписала в свой outbox-чат (`5-tech-backlog/chat/be.md`)
**фрагменты** `Jwt:SigningKey` (`Privacy ...2026=` / `gateway ...minE=`) — чтобы сравнить
ключи. Репозиторий **публичный**, чат коммитится в git → фрагменты ушли в историю
(коммит `2aa7bf9`). Обнаружено вручную, уже после пуша.

### Почему петля это не поймала
- В XDiary есть `guard-paths` (зоны ролей) и `check-chat` (формат строк), но **нет
  проверки секретов** — правило «секреты только в `.env`/Secrets» было только в `AGENTS.md`.
- Чат — текстовый файл в git: любая вставка ключа становится публичной навсегда
  (из истории не убрать без force-push).
- Роль сама помогла диагностике (сравнить ключи) и не восприняла значение как секрет.

### Что сделать в LoopMaker
1. Добавить в `AGENTS.md` (§4 «Чат» и/или §6) правило: **в чат/задачи/коммиты не
   пишем ключи, токены, пароли и их фрагменты**; для сравнения — «ключи различаются,
   сверка через Secrets».
2. Дать шаблонный линтер для проектов петли — `tools/check_secrets.py` (или инструкцию
   в §7 «Автоматика»): паттерны `SigningKey`/`apiKey`/`password=`/длинные base64/hex
   в `chat/*.md`; job в CI на push.
3. В §7 (`Автоматика`) добавить строку `guard-secrets` в таблицу workflow.
4. В §9 «Антипаттерны» — пункт «секрет в чате/коммите» (как в XDiary 03.11).

### Процедура при утечке (для петли)
1. Зачистить в рабочем файле (аутбокс автора).
2. **Ротация** секрета (Secrets + `.env` на стендах) — координатор поручает DevOps.
3. Из git-истории не убирать без force-push (риск); ротация обязательна.
4. Записать инцидент в `TODO`/`CHANGELOG` проекта.
