## TODO-1: правило против утечки секретов в петле (после инцидента в XDiary)

**Статус:** закрыт 2026-11-04 (реализовано в LoopMaker; в XDiary осталось портирование — см. «Открыто»)
**Источник:** инцидент в XDiary, 2026-11-03

### Что случилось
Роль **BackEnd** вписала в свой outbox (`5-tech-backlog/chat/be.md`) **фрагменты**
`Jwt:SigningKey` («...2026=» / «...minE=»), чтобы сравнить ключи. Репозиторий **публичный**,
чат коммитится → фрагменты ушли в историю (коммит `2aa7bf9`). Обнаружено вручную, уже после пуша.

**Второй заход (04.11):** сообщение координатора *об этом инциденте* само процитировало
те же хвосты — уже в `chat/tl.md`. То есть «объяснить, что произошло» естественнее, чем
промолчать, и запрет в голове не срабатывает дважды.

### Почему петля это не поймала
- Правило «секреты только в `.env`/Secrets» жило только в `AGENTS.md` — без гейта.
- Регекс в `XDiary/tools/check_secrets.py` требует значение `[A-Za-z0-9+/=_-]{20,}` и
  **явно пропускает значения с `...`**. То есть ровно форма инцидента («...2026=»)
  невидима: длина 4–8 символов, многоточие. Проверено на четырёх образцах — 3 из 4 MISS.

### Сделано
1. **`AGENTS.md` §13 «Секреты в петле»** — три инструкции (значения и фрагменты только
   в `.env`/Secrets; сравнение — `keycmp.py`; инцидент описываем без цитат), гейты,
   границы линтера, процедура при утечке (зачистить → ротация → историю не переписывать).
   Плюс: §4 правило 6 (чат), §7 строка `guard-secrets.yml`, §9 антипаттерн, §10 в список
   «копировать как есть».
2. **`tools/check_secrets.py`** — конфиг-driven (`loop.config.json` → `secrets.paths`),
   два класса правил:
   - `assign` — по **намерению**: имя ключа (`SigningKey|apiKey|password|token|…`) + `=`/`:`
     + непустое значение. Ловит фрагменты, которые форма не выдаёт;
   - `shape` — base64/hex/JWT/`ghp_`/`AKIA`/TG-бот/PEM + `fragment-ellipsis` (`...2026=`).
   Режимы: весь обход / `--range BASE..HEAD` (для CI, сканирует только пушимое), `--json`.
   Значение никогда не печатается (только правило, файл, строка, длина).
3. **`tools/keycmp.py`** — безопасное сравнение: «совпадают/НЕ совпадают» + `len` +
   `sha256[:8]`. Значения не выводятся. Причина: без такого инструмента агент вынужден
   печатать фрагменты, чтобы ответить на вопрос «ключи одинаковые?».
4. **`templates/guard-secrets.yml`** — workflow для нового проекта: `--range`, пин на
   `LOOPMAKER_REF`, без значений в логах.

## TODO-3: переход на 8 статусов (подготовлено, ждёт сигнала)

**Статус:** подготовлено 2026-11-06, **внедрение не начато** (ждём сигнала владельца)
**Документ:** [STATUSES.md](STATUSES.md)

### Решение
Было 5 (`Открыта/В работе/На проверке/Закрыта/Отклонена`), стало **8**:
`Идея → На проработке → ToDo → В работе → (В паузе) → На проверке → Закрыта` + `Отклонена`.
Две правки к исходной идее владельца: «На проработке» вместо «Проработана» (это активное
состояние, у него есть назначенный проработчик — например Arch проверяет идею BE на
соответствие ADR) и возвращённая `Отклонена` (иначе «не делаем» висит в ToDo навсегда).
`Открыта` → `ToDo` (то же значение, без смешения с «ещё не проработано»).
`В паузе` — главное приобретение: сейчас блокировка выглядит как «В работе» и на 72-м часу
попадает в `sweep` как «зависла».

### Что готово
- **[STATUSES.md](STATUSES.md)** — таблица статусов (кто ставит, обязательные поля, колонка
  Projects), матрица переходов 8×8, пороги обхода по статусу, маппинг доски, миграция,
  чеклист по файлам, риски, порядок внедрения.
- **`tools/status_lint.py`** — значение из списка, синонимы с подсказкой (`Открыта → ToDo`),
  обязательные поля под статус, **два уровня**: ошибки (вне списка; `Закрыта` без `Результата`;
  `В паузе` без причины/разблокировки) и предупреждения (`Проверяет`, `В работе с`, `Причина`,
  `Прорабатывает` — они бэкфиллятся). Флаги: `--report`, `--strict`, `--json`, `--statuses`.
- **`tools/migrate_statuses.py`** — dry-run по умолчанию, `--write` для применения, защита
  «целевой статус должен быть в конфиге», хвост в скобках (`Закрыта (TL проверил)`) сохраняется.

### Замер на XDiary (ничего не меняли)
- `status_lint` с набором из 8: **41 нарушение = 15 ошибок + 26 предупреждений**
  (14× `Закрыта` без `## Результат`, 1× `Открыта`; предупреждения: `Причина` 13,
  `Проверяет` 9, `В работе с` 4).
- `migrate_statuses` dry-run: затронет **1 файл** (`DO-022`: `Открыта → ToDo`).
