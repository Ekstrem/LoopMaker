# AN-01. Почему в коммиты агентов попадают чужие файлы, если есть зоны

**Статус:** анализ для ретро (не норма). **Дата:** 2026-11-07. **Автор:** @LM.
**Метод:** прогон по последним 400 коммитам `XDiary` + `loop.config.json` (зоны/shared/coordinator)
+ ручной разбор инцидентов. Скрипт анализа — временный, в репозиторий не кладётся.

---

## 1. Результат замера

| Показатель | Значение |
|---|---|
| Коммитов просмотрено | **400** |
| Из них merge-коммитов | **37** |
| **Без роли в префиксе** (`chore(chat)`, `Merge …`, human) | **170 (42,5%)** — `check_paths` их **пропускает** |
| По ролям | `tl` 73, `do` 70, `te` 49, `fe` 15, `lm` 11, `be` 5, `ar` 2, не распознано 5 |
| **Класс A: файлы вне зоны роли** | **1 коммит** (`c9d4db8` — `lm`: `chat/README.md`, `tools/*`) |
| **Класс B: чужая работа ВНУТРИ своей зоны** | **2 случая** (`lm` пишет в `tools/` — зона @DO): например `a51d1a5`, куда попал `tools/health.py` авторства @LM |

Главный вывод из цифр: **путевой гейт почти не ловит чужие файлы — 1 случай на 400 коммитов.**
А реальные случаи «чужих файлов в коммите» (`a51d1a5`, `2aa7bf9`, `wip(be)`) — **другой класс**,
который по путям не виден вообще.

---

## 2. Пять механизмов, а не один

### М1. Зона — про **каталог**, а чужая работа — про **авторство**
`zones` говорит «@DO пишет в `tools/`». Но `tools/` — не «файлы @DO», а **общий каталог**:
@LM пишет инструменты в `LoopMaker` и синкает копию в `tools/`. Когда @DO делает
`wip(do)` по своей зоне, он захватывает **и чужие правки в этом каталоге** — так `a51d1a5`
втянул `tools/health.py` (@LM). Путевой гейт этого не видит: путь **внутри** зоны коммитящего.

> Это ответ на вопрос «почему при ограничениях чужие файлы попадают»: ограничение —
> **по каталогу**, а конфликт — **по авторству**. Каталоги общие, авторство у каждого своё.

### М2. Общий **index**, а не только дерево
`git add -A` / `git commit -a` / `wip --all` кладут в индекс **всё**, включая чужие
незакоммиченные правки. Индекс — общий ресурс: кто первым коммитит, тот и «автор» чужих строк.
`wip.py --role` сужает по зонам, но зона (см. М1) шире авторства.

### М3. 42,5% коммитов **без роли** — гейт их пропускает по устройству
`check_paths.py` определяет роль по префиксу; `chore(chat)`, `Merge …`, человеческие сообщения
роли не имеют → «пропущено без роли». То есть **почти половина истории неподконтрольна** гейту,
и это не баг, а заложенное правило.

### М4. У **@LM нет зоны** в `loop.config.json`
У процессной роли нет `core`/`service`: её файлы (`AGENTS.md`, `loop.config.json`, `chat/lm.md`,
`docs/**`) формально не проверяются. Мой `c9d4db8` нашли только потому, что я сам написал
проверку, а не потому, что гейт умеет.

### М5. Merge несёт обе стороны
37 merge-коммитов: в них файлы «обеих сторон» по определению. Любая путевая проверка либо
их пропускает, либо красит всегда.

## 3. Что предлагается (кандидаты, не нормы)

| # | Мера | Ловит | Цена |
|---|---|---|---|
| 1 | **Коммит по явным путям**: `git add -- <path>` / `git commit -- <path>`; запрет `-a`/`--all` в ролях | М2 | 0, привычка |
| 2 | `wip.py`: **`--only-paths` по умолчанию** (только изменённые файлы, а не вся зона) — уже фигурирует как DO-043 | М1, М2 | ~20 строк |
| 3 | **`check_paths` не пропускает безликие коммиты**: allowlist для бота/merge, иначе — требует префикс | М3 | ~15 строк |
| 4 | **Зона для `@LM`** явно (`AGENTS.md`, `loop.config.json`, `chat/lm.md`, `docs/pdr`, `docs/drafts`) | М4 | 5 строк конфига |
| 5 | **Манифест авторства для общих каталогов**: `tools/` = @DO + @LM (по списку файлов из `.sources.json`), `docs/` = @LM+@DO; гейт проверяет пару «роль → путь» по манифесту, а не по каталогу | М1 | полчаса + тест |
| 6 | **Pre-commit hook**: отказ, если в индексе путь вне зоны/манифеста роли, или если в индекс попал файл, изменённый после последнего коммита не тобой | М1–М4 | ~40 строк, обязателен `--no-verify`-осознанно |
| 7 | Отдельные **worktree** на роль | М1–М5 целиком | дорого, ломает «одно дерево» |

Рекомендация: **1 + 2 + 3 + 4** дёшево и закрывает 90% (М2–М4); **5** — только если решим,
что общие каталоги остаются; **6** — после того, как 1–4 покажут, что инциденты не ушли.

---

## 4. Ограничение самого замера

Мой скрипт **ошибся** на `docs(drafts)` — распознал как роль `drafts` (3 коммита), потому что
префиксы `docs`/`do` разбираются жадно. Это ровно та же болезнь, что и у `check_paths`:
**атрибуция по строке коммита хрупкая**. Если делать гейт на авторство — определять роль надо
не регуляркой, а явным полем (`Signed-off-by`/trailer `Role:`), иначе получим ложные «чужие файлы»
в обе стороны.
