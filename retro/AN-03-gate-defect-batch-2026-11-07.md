# AN-03. Пакет дефектов гейтов — причины, риски, решения (2026-11-07)

| Поле | Значение |
|---|---|
| **Дата** | 2026-11-07 |
| **Собрал** | @LM (по фактам TL/AR/DO, проверено независимо) |
| **Класс** | дефекты критерия (ложный красный / пробел / слепая зона), НЕ новые нормы |
| **Решение владельца** | «записал артефакт → принимай решение и исправляй» |

Правило из AN-02 продолжается: **каждый дефект гейта — кейс** (что/причина/риск/фикс/проверка).
Здесь шесть дефектов одним пакетом; новые нормы (WIP-лимит, допуски `chat_lint`, строки-счётчик)
в этот пакет **не входят** — они до ретро.

## 1. `check_rule_docs` — ложный красный на служебных путях

- **Причина:** правило «абсолютный домашний путь» не различает персональные
  (`C:\Users\…`, `/Users\…` — хранилище токена) и сервисные (`/home/deploy`,
  `/home/ubuntu`, `/home/runner` — документация ранбука). 29 из 33 замечаний — сервисные.
- **Риск:** гейт краснеет на верном тексте → «красный фон» → роли перестают верить гейту.
- **Решение:** allowlist по шаблону пути для сервисных аккаунтов (только `7-deploy/runbooks/**`);
  путь к файлу кредов — `error` везде, allowlist его не снимает.

## 2. `check_adr_refs` — пробел «Принято → Отклонено»

- **Причина:** гейт сверяет номера/статусы упомянутых ADR, но не ловит «ссылка из
  `Принято` ведёт в `Отклонено`». Случай `ADR-005 → ADR-029` поймал человек.
- **Риск:** связность ADR нарушается незаметно; читатель идёт по ссылке в отменённое решение.
- **Решение:** переход «`Принято` → `Отклонено`» = `rc=1`.

## 3. `check_awaits` — ложный красный на свежих выдачах и на @EX

- **Причина:** (а) гейт не смотрит на возраст — красный уже через минуту после выдачи;
  (б) строки `@EX` (решения владельца) считаются «висящими ролями», хотя у владельца нет
  outbox-обязанности отвечать «принято».
- **Риск:** гейт вечно красный → «красный фон»; свежая работа выглядит зависшей.
- **Решение:** `--max-age-minutes N` (по умолчанию 60, `--strict` валит только по строкам
  старше N); строки `@EX` — в отдельную секцию, не валят гейт ролей.

## 4. `guard-tools` — манифест копий отстал

- **Причина:** @DO правил `tools/check_canon.py` и `tools/check_api_index.py` (копии),
  источник/манифест не синхронизирован → шаг «копии совпадают с манифестом» красный.
- **Риск:** копии расходятся с источником; гейт блокирует merge у всех.
- **Решение:** свести копии с источником + обновить манифест (`.sources.json`).

## 5. `lock-sync` — пишет lock из git

- **Причина:** `lock-sync` положил lock с 8 тегами, которых нет в реестре (взял из git).
- **Риск:** lock не отражает реестр → деплой/сборка по неверному списку образов.
- **Решение:** `lock-sync` **никогда** не пишет lock из git — только из реестра/фактических
  образов; git может служить источником сравнения, но не источником записи.

## 6. `check_secrets` — слепая зона (whitelist вместо blacklist)

- **Причина:** `default_paths` = whitelist (`5-backlog`, README, …) → не покрыто `6-msa/**`,
  `7-deploy/**/*.md` (ранбуки), `9-tests/**/*.md` (отчёты), `04-architecture`, `03-ddd`, фронт.
  Ранбук/отчёт — самое вероятное место утечки; мы сами выписывали значение в файл-кандидат.
- **Риск:** реальный секрет в ранбуке/отчёте не ловится (дыра жила ~3 месяца под видом allowlist).
- **Решение:** сканировать **всё**, кроме явных исключений (`**/bin/**`, `**/obj/**`,
  `**/node_modules/**`, `.git/**`); `postgres` (дефолт локального dev) — в `SKIP_VALUES`;
  hex-идентификаторы уже пропускаются (AN-02).

## Проверка пакета (§5.4)

Каждый дефект: `--selftest` (дефект → находка/`rc=1`, норма → `rc=0`) + два прогона на реальном
дереве. Правка — в источнике (LoopMaker, если тул там есть) + копии XDiary; коммит отдельно.
