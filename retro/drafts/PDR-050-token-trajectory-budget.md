# PDR-050 — Траектория агентов: снижение расхода токенов

| Поле | Значение |
|---|---|
| **Статус** | обсуждается |
| **Владелец** | @LM (предложение); решение — @EX |
| **Согласования** | не запрашивались (@DO, @TL, роли-пилоты) |
| **Дата** | 2026-11-26 |
| **Заменяет** | — (измерение: D-35, PR #11 LoopMaker) |

## Контекст

Замер D-35 (16 сессий XDiary, 28.10–25.11): 26,9 млрд provider-токенов; **99,2% —
cache read** перечитываемого контекста, медианное давление ~442k на запрос,
61 145 шагов; свежий input 0,5%, output 0,2%. Чат: 5 408 сообщений; FE+DO — 97%
символов длинных (≥1000); 34% строк мультиадресные (1,43× адресаций); TL+DO — 53%
входящих адресаций. Формула: **расход = шаги × давление**; ack-ходы (0,5%) и
дедупликация (<0,5%) — не рычаги. Указание владельца 2026-11-26: решения —
«на уровне ADR», т.е. полный PDR-формат.

## Варианты

| Вариант | Плюсы | Минусы | Цена |
|---|---|---|---|
| **A. Статус-кво** | ноль работ и рисков; baseline для сравнения | расход растёт с длиной итераций: тред живёт месяц и перечитывает ~442k на каждом шаге; эффект мер недоказуем | 0 |
| **B. Механика** (рекомендую первым): ledger + батчирование пробуждений 60 с (крит — сразу) + lifecycle тредов на границе итерации + graphify для ориентировки | бьёт в 99,2% (контекст) и в число шагов; не требует дисциплины ролей; откат по порогу | правка плагина + ребут DSH; треды открывает владелец; сброс треда ломает тёплый cache | @LM ~2 дня + 2 ребута + открытие тредов |
| **C. Нормы ролей**: дайджест+ссылка для ≥1000 симв. (FE/DO), fan-out одному адресату по умолчанию, state-aware whip | −16,9% объёма чата (симв.); чат внутри контекста — двойной эффект | процессные нормы: привыкание, гейт, риск отрезать нужную деталь | @LM ~1 день + ретро-вердикт |
| **D. LLM-фильтр / смена модели** | — | PDR-041 припаркован (фильтр дороже пустоты); смена модели ≠ меньше токенов | отброшено |

## Решение

**B → C поэтапно, A — база сравнения.** Сначала механика: не требует дисциплины и
бьёт в главный множитель; нормы (C) — после измеримого эффекта B. Условия пересмотра:
`missed_critical > 0` в любом пилоте, давление не упало за пилот, uncached input
вырос без компенсирующего падения общего расхода.

## Критерий приёмки и метрика

- Ledger отчёт без LLM, без тел сообщений/секретов; selftest на replacement/retry/нет-usage.
- Пилот батчирования (1 неделя): ходов-доставок −30% при тех же сообщениях, `missed_critical = 0`.
- Lifecycle-пилот (DO, AR): медианное давление на новую задачу ниже baseline; компакций меньше.
- Мера C: p95 длины FE/DO-реплик падает; решения проверяемы по карточкам.
- Дата проверки эффекта: 2026-12-03 (батчирование), конец итерации (lifecycle).
