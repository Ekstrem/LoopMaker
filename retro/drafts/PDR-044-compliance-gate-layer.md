# PDR-044: Контроль соблюдения правил — гейт-слой, а не субагент на каждый шаг

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (по отчётам 6 ролей 2026-11-11 + вопросу владельца) |
| **Затронет** | pre-commit хук, CI-гейты, субагент-фильтры |
| **Дата** | 2026-11-11 |

## 1. Контекст и проблема

Правила §2/§5 записаны («`git commit` без путей запрещён», «статус → `stats.py --write` в том
же коммите»), но за сутки на них наступили **4 роли из 6** независимо: TL, AR, TE (коммит
`a086700f8` с чужими путями), DO (через `--no-verify`). Вывод: **правило без гейта = пожелание**,
а не запрет. Вопрос владельца: проверять ли соблюдение **субагентом на каждом шаге**.

## 2. Что не меняется

Сами правила §1–§7 не меняются. 40 CI-гейтов (см. `METRICS.md`, таблица B) остаются. Субагент-фильтры
для «шум/решение» (PDR-041) — это про **внимание**, а не про **соблюдение**; этот PDR их не отменяет.

## 3. Варианты

### A. Субагент-аудит на каждый шаг роли

**+** видит «суждение», а не только строки (например, «это ли выход за зону по смыслу»).
**−** дорого: каждый шаг = вызов субагента = токены + латентность; **недетерминирован** (фильтр
v1 ошибся 3 из 4); правила-механики (пути, формат, коммит) проверяются регексом точнее, чем LLM.

### B. Детерминированный гейт-слой (pre-commit хук + CI)

**+** мгновенно, бесплатно, не ошибается; срабатывает на том, что уже формализуемо.
**−** покрывает только **механические** правила, не «суждение»; нужна настройка хука на машинах ролей.

### C. Гибрид: B как фундамент, субагент — только для суждения (рекомендую)

Механические правила → хук/CI. «Что требует внимания человека» → субагент-фильтр по входящим
(не на каждый шаг, а по потоку сообщений).

**+** дешёвый детерминированный слой там, где он возможен; субагент — только там, где нужна
классификация; оба слоя не конфликтуют.
**−** две вещи вместо одной (хук + фильтр); но это разные задачи.

## 4. Предлагаемый вариант

**C.** A отброшен: проверка «правило нарушено?» на 90% детерминирована, LLM для неё избыточен и
ненадёжен (доказано пилотом v1). B отброшен в одиночку: есть класс, который гейт не видит
(«вывод по отставшему origin», «дефект-плечо без прогона») — там субагент-фильтр полезен.

## 5. Риски и митигация

| Риск | Цена | Митигация | Сигнал |
|---|---|---|---|
| Хук мешает коммитам (ложный запрет) | роли встали | хук только блокирует, подсказывает команду; `--no-verify` запрещён | жалобы «не коммитится» |
| Хук обходят (`--no-verify`, как DO) | гейт не работает | CI-проверка дублирует хук (post-push) | коммит без хук-следа прошёл |
| Субагент-фильтр ошибается в суждении | пропущен крит | консервативность: сомнение → эскалация | крит, о котором узнали позже часа |
| Гибрид = две точки отказа | больше кода | хук и фильтр независимы, падение одного не блокирует другое | отдельный отказ каждого |

## 6. Как проверим

- хук ловит: `git commit -m "x"` без `-- <paths>` → отказ; с чужим путём в индексе → отказ; чистый коммит → проходит;
- за итерацию: **0** коммитов ролей с чужими путями (сегодня 4+);
- субагент-фильтр: **0** пропущенных крит-событий за пилот.

## 7. Стоимость и порядок

1. @LM: pre-commit хук (Python, ~30 строк) + его установка ролям — полдня.
2. @DO: дублирующий шаг в CI (post-push `git show --name-only` против зоны) — его зона, ~15 строк.
3. Субагент-фильтр — уже в пилоте (PDR-041), не дублировать.

## 8. Решение

Владелец @EX: принять C (рекомендую) или сузить до B.
