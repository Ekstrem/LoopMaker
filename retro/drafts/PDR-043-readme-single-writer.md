# PDR-043: `README.md` — общий генерируемый файл, который правят все

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (вопрос @TL 02:50, находка @AR) |
| **Затронет** | правило §2 «статус меняешь — обнови таблицу», `stats.yml`/`stats.py`, роли |
| **Дата** | 2026-11-10 |

## 1. Контекст и проблема

`README.md` содержит таблицу статусов и **генерируется** `python tools/stats.py --write`.
Правило §2 требует от **каждой** роли обновить её перед пушем. Значит любая параллельная работа
двух ролей пересекается в одном файле — это гарантированный конфликт по конструкции.
У @AR на этом упал cherry-pick.

Замер (08–10.11, `origin/main`): README правлен в **13 коммитах из 1020 (1%)**, авторы —
`bot` 5, `ar` 4, `be` 3, прочее 1. То есть **бот уже пишет таблицу**, а роли — редко.
Механизм реален, частота пока низкая: цена — не «много конфликтов», а «каждый конфликт
дорог, потому что общий файл».

## 2. Что не меняется

Гейт `stats.py --check` остаётся: отставание таблицы от задач по-прежнему ловится.
Источник правды — карточки (`Статус:`), а не README.

## 3. Варианты

### A. Статус-кво: каждая роль делает `--write` перед пушем

**+** ничего не менять; таблица всегда свежая локально.
**−** общий файл = конфликт при любой параллельной работе; конфликт бьёт по чужому коммиту
(случай @AR), а не по автору изменения статуса.

### B. Единственный писатель — бот (предложение @TL)

Роли **не трогают** README; после пуша workflow делает `stats.py --write` и коммитит таблицу
(`[skip ci]`, fetch+merge+retry — как в `lock-sync`). Гейт остаётся.

**+** пересечение исчезает полностью: файл пишет один процесс в одном месте.
**−** таблица в `main` отстаёт до прогона бота (минуты); нужен аккуратный push бота (гонка с ролями).

### C. Убрать таблицу из README, оставить числа в дашборде

**+** общего файла нет вообще.
**−** README перестаёт отвечать «что в работе» — теряется входная точка для человека.

## 4. Предлагаемый вариант

**B.** Он устраняет причину (общий файл с несколькими писателями), сохраняет гейт и таблицу.
A отброшен — механизм гарантированного конфликта, C — теряет читаемость README.

## 5. Риски и митигация

| Риск | Цена | Митигация | Сигнал, что наступил |
|---|---|---|---|
| Таблица отстаёт до прогона бота | минуты несоответствия | бот на `push` + `schedule`; гейт сверяет **статусы карточек**, а не текст README | `stats --check` красный дольше одного прогона |
| Бот толкается с ролями | rejected push | `[skip ci]` + fetch/merge/retry ×3 (паттерн `lock-sync`) | ≥3 rejected подряд |
| Роль по привычке правит README | конфликт возвращается | `check_paths`-подобная проверка: коммит роли не должен менять README | появление README в коммитах ролей |
| Двойной источник правды | расхождение | README — производная, карточки — источник; правило записано в §2 | расхождение таблицы и `stats.py --print` |

## 6. Как проверим

- за неделю: **0** коммитов ролей, меняющих `README.md`; конфликтов на README — **0**;
- `stats.py --check` зелёный на `main` ≥95% прогонов;
- таблица отстаёт не дольше одного прогона бота.

**Не сработало** (откат к A): `stats --check` краснеет на `main` чаще, чем раз в сутки, или
таблица систематически отстаёт.
