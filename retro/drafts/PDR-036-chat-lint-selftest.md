# PDR-036. chat_lint: самопроверка + будущие штампы + канон статус-строки

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (предложения @DO/@TE/@TL) |
| **Затронет** | `tools/chat_lint.py` (источник LoopMaker + копия XDiary) |
| **Дата** | 2026-11-05 |

## 1. Контекст — что за скрипт и за что отвечает

`chat_lint.py` — **линтер формата чата**. Формат строки чата
(`- [YYYY-MM-DD HH:mm] → @КОМУ: текст`) — это **контракт трёх потребителей**:

1. `lib/parse.js` (плагин `dsh-loopmaker`) — доставляет сообщение адресату в его сессию;
2. `tools/merge_chat.py` — собирает авто-сводку чата;
3. `tools/chat_bot.py` — бот.

Если роль напишет строку не по формату (без двоеточия, без времени, два адресата через
`+`), строка **молча выпадает**: ни доставки, ни сводки, ни ошибки. Реальный случай 03.11:
6 сообщений с двумя адресатами не дошли — заметил человек, а не система.

**Что делает:** сканирует `<backlog>/chat/*.md`, находит строки, которые канонический
регекс не разбирает, и пишет замечание автору в `chat/_lint.md` (мост доставляет его в
сессию автора). Плюс проверяет метки времени (будущее, немонотонность внутри файла).

**«Софт стейт» (мягкий режим) — что это.** По умолчанию линтер «мягкий»: пишет замечания
и предупреждения (`::warning::`), но **не валит CI**. «Жёсткий» режим включается флагами
`--check` (код 1 при находках) и `--strict-times` (метки в будущем/немонотонные — ошибка).
То есть «софт» = заметил и предупредил без блокировки; «хард» = ошибка с `rc=1`.

## 2. Проблема (и причина)

Три пробела, каждый с ценой:

1. **Нет `--selftest`.** chat_lint — **единственный** из 24 инструментов в `ci-guards` без
   самопроверки (604 строки, 0 упоминаний). **Причина:** его писали раньше, чем появилась
   норма §5.4 «selftest внутри прогона»; норму ввели позже, а до этого линтера руки не дошли.
   **Следствие:** правку chat_lint нельзя проверить автоматически — «линтер работает»
   держится на памяти, а не на тесте.
2. **Будущие штампы — ложный зелёный.** `--strict-times` отвечает на вопрос «метка монотонна
   внутри файла?», а **не** «метка в будущем?». @TE замерил: при 59 штампах `2026-11-16` и
   машине `2026-11-05` → `rc=0`, то есть будущее не ловится, потому что проверяется не то.
3. **Канон статус-строки не проверяется.** Правило «сменил `**Статус:**` → строка `<ID> A → B`
   в чат в том же коммите» (§2 AGENTS) держится на дисциплине, инструмент его не проверяет.

## 3. Варианты и риски

| Вариант | Что | Плюсы | Риски |
|---|---|---|---|
| **A. Добавить `--selftest` + 2 проверки** | самопроверка + «будущее» отдельной ошибкой + канон `<ID> A → B` | закрывает все три пробела; линтер становится проверяемым | ~полдня; правка в источнике + синхронизация копии (`guard-tools`) |
| **B. Записать исключение** | оставить без selftest, задокументировать «причину» | 0 работы | «исключение без проверки» = тот же класс «гейт, который не может провалиться»; копит долг, а не чинит |

**Рекомендация: A.** chat_lint — живой линтер с тремя пробелами, а не «особый случай»;
исключение (B) оправдано только для мёртвых/одноразовых скриптов.

## 4. Предложение (вариант A)

1. **`--selftest`** — кейсы: формат (канон/неканон), будущий штамп, фантомная метка,
   канон `<ID> A → B`; негативный контроль.
2. **Будущие штампы** — считать «штамп в будущем» отдельной ошибкой в `--report`/`--strict-times`
   (не только «нарушение порядка»).
3. **Канон `<ID> A → B`** — гейт: каноническая строка смены статуса в чате ⇒ смена `**Статус:**`
   той карточки в том же коммите.

## 5. Цена

~полдня (selftest + два предиката) + синхронизация копии в XDiary.

## 6. Как проверить

- `chat_lint.py --selftest` — зелёный;
- будущий штамп (`2026-11-16` при машине `2026-11-05`) → `rc=1`;
- строка `<ID> A → B` без смены статуса в том же коммите → `rc=1`.
