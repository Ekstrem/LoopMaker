# PDR-041: Доставка чата ролям — фильтр-субагент вместо «пушить всё»

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (пилот 1 час + идея владельца) |
| **Затронет** | доставка чата ролям (сейчас `dsh-loopmaker`), скоуп ролей |
| **Дата** | 2026-11-10 |

## 1. Контекст

Сейчас `dsh-loopmaker` доставляет **каждую** строку `→ @Роль` в сессию роли. Роль видит всё
подряд — статусы, повторы, шум — и фильтрует сама. Для @LM опробован противоположный механизм:
**субагент-фильтр** читает чат напрямую из `origin/main`, классифицирует и отвечает шаблоном,
а критичное эскалирует. Пилот (1 час, 6 проходов) отработал чисто: 2 новые строки `→ @LM`,
1 шаблонный ответ, крит 0, потерь в git нет.

## 2. Проблема

- Плагин пушит **всё** → роль жжёт контекст на нерелевантные строки и может пропустить крит
  среди шума;
- «прочитай сам и отфильтруй» не работает как норма: роли реагируют на шум или молчат на крит.

## 3. Решение (обобщение на все роли)

1. Для каждой роли — **фильтр-субагент** (либо один общий фильтр с шаблонами по ролям).
2. Субагент читает чат **только из `origin/main`** (не через плагин, не локальное дерево).
3. **Классификация**: крит (STOP / инцидент git / секреты-утечка / `@EX` / прямой вопрос без
   факта) → эскалация роли немедленно; «ни о чём» (предложение нормы/гейта, повтор,
   наблюдение, статус) → шаблон.
4. **Шаблон по роли** (у @LM: «общение через владельца или на ретро»; у остальных ролей —
   свой дефолт, решается на ретро).
5. **Запись только в чистое окно**: fetch → merge → edit → commit → push с ретраем; чужое
   незакоммиченное WIP не трогать (не `stash`/`reset`).

## 4. Цена

Субагент-час дешевле, чем контекст роли на шум. Открытые вопросы: один общий фильтр или по
фильтру на роль; период работы (час / смена / постоянно).

## 5. Как проверить

Пилот @LM уже прошёл. Для других ролей — тот же замер: сколько строк доставлено против
сколько реально потребовало реакции (и сколько крита пропущено/поймано).
