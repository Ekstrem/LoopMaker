# D-11. `status_lint` предупреждает про статус с пояснением

| Поле | Значение |

| **Затронет** | @LM (источник `LoopMaker/tools/status_lint.py`), @DO (копия в `tools/`), все роли (пишут статусы) |
| **Дата** | 2026-11-07 |

## Проблема

У **23** задач статус записан с пояснением: `Закрыта (TechLead: …)`, `Отклонена (свод…)`.
`stats.py` нормализует статус **по подстроке** (`normalize()`, строка ~49: «закрыт»/«отклон»),
поэтому такие задачи попадают в правильную колонку — но по **неявному контракту**:
если пояснение не содержит ключевого слова (например `Закрыта по решению владельца`), задача
**молча** уедет в другую колонку, и никто этого не заметит — ровно как не заметили отсутствие
папки `tl/` в `task_folders` (`stats` и README были согласованы, но оба не видели реальность).

## Предложение

`status_lint` добавляет **предупреждение** (не ошибку) для статуса с пояснением:

```
задача TE-045: статус «Закрыта (TechLead: …)» — пояснение в поле статуса;
канон: «Закрыта», пояснение — в «## Результат» или отдельной строкой
```

Плюс `stats.py` при нормализации — **считать неизвестный статус неизвестным** (отдельная
колонка/предупреждение), а не молча относить к ближайшей подстроке.

## Цена

~15 строк в `status_lint.py` + 2 теста; правка в источнике = синк копии (D-10 guard это
как раз и защищает). Риск ложных срабатываний: предупреждение → не блокирует CI.

## Как проверить

- на текущем дереве: предупреждений **23** (по числу статусов с пояснением), ошибок 0;
- задача со статусом `Закрыта` — предупреждений нет;
- `stats.py --check` остаётся rc=0.

## Что мешает принять сейчас

Правило не вводим до ретро (решение владельца); правка инструмента + копии — двухсторонняя
(источник @LM, копия @DO), то есть посреди цикла это лишняя координация.
