# PDR-047 — план-чеклист миграции (v2, согласовано с владельцем)

## 0. Решения (зафиксировано)

| Вопрос | Решение |
|---|---|
| Ветки | **`role/<name>`** (одна ветка на роль) |
| Чат — куда | **та же директория `chat/*.md`**, правило outbox не меняется |
| Чат — кто коммитит | **бот** (часть `dsh-loopmaker`): смотрит файлы чата и коммитит/пушит |
| Чат — как бот коммитит | **только `chat/*.md`**, никогда `git add .` |
| Плагин читает | **`origin`** (`git show origin/main:…`), а не локальную папку |
| Поллинг | v1 — фиксированный **15–30 сек**; v2 — адаптивный (5 сек при активности, до 15 мин простоя) |
| Per-role токены | **не нужны** — branch protection `main` + PR + merge queue + `check_paths` |
| Красный гейт | изолирован в PR, `main` зелёный; кнут по PR; ложный гейт = дефект (§5.4) |
| Готово, исполнитель спит | **передача патча** — координатор применяет через 1 час |
| Порядок | **сначала B2 (чат-бот), потом B1 (ветки)** |

---

## 1. Фаза 1 — B2: чат через бота (правило ролей не меняется)

### 1.1 Модель
- [ ] Роль пишет строку в **свой** `chat/<role>.md` (общее дерево, как сейчас). Никакого отдельного inbox.
- [ ] Бот замечает изменение и **коммитит + пушит** `chat/*.md` в `origin`.
- [ ] Плагин читает **`origin`**, доставляет из свежего чата.

### 1.2 Бот (часть плагина) — коммиттер
- [ ] Поллинг: v1 фиксированный **15–30 сек**; v2 адаптивный (5 сек → 15 мин).
- [ ] Коммитит **только `chat/*.md`** (`git add chat/*.md`), НЕ `git add .` — страховка от захвата чужого WIP.
- [ ] Перед push: `fetch` → `merge --ff-only origin/main` → если rejected → повторить на свежем `origin`, применив только chat-изменения.
- [ ] Нет изменений в `chat/*.md` → **нет коммита**.
- [ ] Префикс коммита `chat(bot):`, флаг `[skip ci]` (не будить CI-прогоны на чат).

### 1.3 Плагин — читать origin
- [ ] `scanFile` читает `git show origin/main:5-tech-backlog/chat/<role>.md`, а не `fs.readFile` локальной папки.
- [ ] `fetch` перед скан-циклом (или по таймеру), чтобы `origin` был свежим.
- [ ] `seen`-дедуп работает по содержимому origin (без изменений в логике).

### 1.4 Гейт перед публикацией (ботом)
- [ ] `check_secrets` по chat-изменениям (стоп при утечке, значение не логировать).
- [ ] `chat_lint --check` (адресат без `@`, метка-мусор — ошибки для новых строк).

### 1.5 Checkpoint B2
- [ ] за сутки **0** конфликтов на `chat/*.md`.
- [ ] коммит чата ≤1 мин после строки роли.
- [ ] плагин доставляет в открытые треды (не 0).
- [ ] **Откат:** роли снова коммитят чат сами, бот-коммиттер выключен.

## 2. Фаза 2 — B1: ветка на роль (код/задачи)

### 2.1 @DO: защита main + merge queue
- [ ] Branch protection `main`: no direct push, require PR, required checks (ниже).
- [ ] Merge queue `group: main` (перетест на свежем `main`, авто-merge зелёного).
- [ ] `pr-create.yml`: push в `role/<name>` → авто-PR в `main`.

### 2.2 Required checks (всегда-включённые)
- [ ] `guard-paths` (`check_paths`) — зона роли.
- [ ] `status_lint` — статусы и обязательные поля.
- [ ] `sync_tools` — копии инструментов совпадают с манифестом.
- [ ] `check_secrets` — секреты/фрагменты.
- [ ] `check_docs_size` — бюджет инструкций (64 КиБ).
- [ ] `check_nul` — маркеры конфликта/управляющие символы.
- [ ] `stats` (`stats.py --check`) — README не отстал от задач.
- [ ] Условные: `check_adr`+`check_adr_refs` (если `04-architecture/`), `check_pdr` (если PDR),
      `check_workflow_paths`/`shape`/`yaml_dups` (если `.github/`), сервисные `ci-backend`/`front` (если затронуты).
- [ ] Полный перечень — по `LoopMaker/METRICS.md` (40 гейтов), мониторы (`health`/`sweep`/`whip`) — НЕ в required.

### 2.3 @LM: правила
- [ ] AGENTS.md §5: роль пушит **только в `role/<name>`**, в `main` — через PR + merge queue.
- [ ] RULES.md §17: git-инцидент остаётся; ветка изолирует конфликты.
- [ ] `commit_whip` → научить адресоваться к **PR/ветке** (кнут по PR), не только к `main`.

### 2.4 Переключение ролей (по одной)
- [ ] Первой @BE, затем FE, TE, DO, AR, PO.
- [ ] Роль: `git checkout -b role/<name> origin/main` → работа → push → PR → merge queue.

### 2.5 Checkpoint B1
- [ ] ни одна роль не пушит в `main` напрямую.
- [ ] PR мержится queue без «untracked would be overwritten».
- [ ] общее дерево чистое.

## 3. Красный гейт в PR-модели (поведение)

- [ ] Красный чек на PR → **PR не мержится**, `main` зелёный, красный изолирован в ветке.
- [ ] Merge queue пропускает только зелёное; красный PR выпадает, ждёт фикса.
- [ ] **Кнут по PR:** чек красный → строка роли в чат «твой PR `role/<name>` → `#NN` красный на `<гейт>` — поправь».
- [ ] Роль чинит → push в ветку → зелёный → queue мержит.
- [ ] Не починила за 1 час → **передача патча** (координатор применяет фикс).
- [ ] Гейт красный **не по делу** → **дефект гейта** (§5.4), чинится гейт, не обход.

## 4. Полный порядок применения (когда агенты остановились)

1. [ ] Остановить DSH/плагин.
2. [ ] Применить §1 (чат-бот): коммиттер + чтение origin + гейт.
3. [ ] Checkpoint B2.
4. [ ] Применить §2 (ветки): branch protection + merge queue + `pr-create.yml` + правило.
5. [ ] Переключить роли по одной (BE первой), Checkpoint B1.
6. [ ] Прогнать `commit_whip`→PR на тестовом красном PR.
7. [ ] `→ всем: новая git-модель включена`.
