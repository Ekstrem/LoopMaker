# PDR-047 — план-чеклист миграции (подробный)

## 0. Решения (зафиксировано владельцем)

| Вопрос | Решение |
|---|---|
| Чат — куда | **отдельная директория** `chat-inbox/` → `chat/` в том же XDiary (НЕ отдельный репо) |
| Per-role токены | **не нужны** — жёсткость даёт branch protection `main` + PR + merge queue + `check_paths` |
| Красный гейт | изолирован в PR, `main` зелёный; кнут роли по PR; ложный гейт = дефект (§5.4) |
| Готово, исполнитель спит | **передача патча** — координатор применяет через 1 час (владелец 2026-11-12) |
| Порядок | **сначала B2 (чат-бот), потом B1 (ветки)** |

---

## 1. Фаза 1 — B2: чат через бота-единственного писателя

### 1.1 Структура каталогов
- [ ] `5-tech-backlog/chat/<роль>.md` — **опубликованный** чат, пишет **только бот** (как сейчас читает плагин).
- [ ] `5-tech-backlog/chat-inbox/<роль>.md` — **staging**, каждая роль пишет строку только в свой inbox-файл.

### 1.2 @DO: бот-коммиттер (`chat-commit.yml`)
- [ ] `schedule` раз в **1 мин** + `workflow_dispatch`.
- [ ] Шаги: `fetch` → собрать непустые `chat-inbox/*.md` → дописать их строки в `chat/<роль>.md` → очистить inbox → `commit [skip ci]` (префикс `chat(bot):`) → `push` (fetch/merge/retry ×3).
- [ ] **Нет pending-строк → нет коммита** (не плодим пустые коммиты 1440/день).
- [ ] Перед публикацией: прогнать `check_secrets` + `chat_lint` по inbox (см. 1.3).
- [ ] Единственный писатель `chat/*.md` — конфликтов нет по построению.

### 1.3 @LM: гейт + правила
- [ ] `tools/check_chat_inbox.py` — валидация inbox перед публикацией: `check_secrets` (стоп при утечке) + `chat_lint --check` (адресат без `@`, метка-мусор) + дедуп по хешу строки.
- [ ] AGENTS.md §4: роль пишет в `chat-inbox/<роль>.md`, НЕ в `chat/*.md`; бот публикует раз в минуту.
- [ ] Плагин `dsh-loopmaker` **без изменений** — продолжает читать `chat/*.md`.

### 1.4 Переключение ролей
- [ ] Роли читают новое правило, пишут в inbox.
- [ ] Проверка: строка роли → бот опубликовал в `chat/*.md` → плагин доставил в открытый тред.

### 1.5 Checkpoint B2 (всё сошлось?)
- [ ] за сутки **0** конфликтов на `chat/*.md`.
- [ ] коммит чата приходит ≤2 мин после строки роли.
- [ ] плагин доставляет (не 0, как сейчас).
- [ ] **Откат**, если нет: роли снова пишут `chat/*.md` напрямую, бот выключается.

## 2. Фаза 2 — B1: ветка на роль (код/задачи)

### 2.1 @DO: защита main + merge queue
- [ ] Branch protection `main`: **no direct push**, **require pull request**, **required checks** (список ниже), **require conversation resolution** (опционально).
- [ ] Required checks: `guard-paths`, `status_lint`, `sync_tools`, `chat_lint`, `check_secrets`, `check_docs_size`, `check_adr`.
- [ ] Merge queue: `group: main` (перетест на свежем `main`, авто-merge после зелёного).
- [ ] `pr-create.yml`: push в `role/<name>` → авто-создание PR в `main` (заголовок `<role>: <id>`, тело из последнего коммита).

### 2.2 @LM: правила
- [ ] AGENTS.md §5: роль пушит **только в `role/<name>`**, в `main` — только через PR + merge queue.
- [ ] AGENTS.md §1: зоны не меняются (карточка в `role/<name>` — та же зона).
- [ ] RULES.md §17: git-инцидент — «восстанавливает один» остаётся; ветка изолирует конфликты.
- [ ] `commit_whip` — научить адресоваться к **PR/ветке**, а не только к `main` (кнут по PR).

### 2.3 Переключение ролей (по одной)
- [ ] Начать с @BE (самая частая запись), остальные пока в `main`.
- [ ] Роль: `git checkout -b role/be origin/main` → работа → push `role/be` → PR → merge queue.
- [ ] После стабилизации BE — FE, TE, DO, AR, PO.

### 2.4 Checkpoint B1
- [ ] ни одна роль не пушит в `main` напрямую.
- [ ] PR мержится queue без «untracked would be overwritten».
- [ ] общее дерево чистое, `git status` пуст.

## 3. Красный гейт в PR-модели (поведение)

- [ ] Красный чек на PR → **PR не мержится**, `main` остаётся зелёным, красный изолирован в ветке.
- [ ] Merge queue пропускает **только зелёное**; красный PR выпадает из очереди, ждёт фикса.
- [ ] **Кнут по PR**: чек на ветке красный → одна строка роли в чат: «твой PR `role/<name>` → `#NN` красный на `<гейт>` — поправь».
- [ ] Роль чинит → push в ветку → чек зелёный → queue мержит.
- [ ] Роль не починила за 1 час → **передача патча** (координатор применяет фикс).
- [ ] Гейт красный **не по делу** (ложное срабатывание) → **дефект гейта** (§5.4), чинится гейт, а не обход.

## 4. Полный порядок применения (когда агенты остановились)

1. [ ] Остановить DSH/плагин (агенты не пишут).
2. [ ] Применить §1 (чат-бот) целиком: workflow + гейт + правило.
3. [ ] Проверить Checkpoint B2.
4. [ ] Применить §2 (ветки): branch protection + merge queue + `pr-create.yml` + правило.
5. [ ] Переключить роли по одной (BE первой), проверить Checkpoint B1.
6. [ ] Прогнать `commit_whip` (кнут по PR) на тестовом красном PR.
7. [ ] Объявить в чате `→ всем: новая git-модель включена`.
