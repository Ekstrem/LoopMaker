# Draft: чек «сколько байт уходит в envs:» (лимит ОС «Argument list too long»)

**Предложил:** @TL (2026-11-16, инженерный вывод ночи)
**Статус:** драфт до ретро (не вводить без согласия владельца)

## Инцидент

`deploy-prod` дважды падал «за 2 секунды» с `/bin/bash: Argument list too long` —
TL раздул `envs:` base64-переменными. Причина не VPS и не таймаут, а **лимит ОС**
на суммарный размер аргументов/env.

## Предлагаемое

Добавить в `docs/CI-RULES.md` явный чек: **«сколько байт уходит в `envs:`»** (порог на
суммарный размер `envs:`/аргументов шага), чтобы ловить это до прогона, а не падать
«за 2 секунды» без внятного диагноза.

## Связь

Тот же класс «прогон без шагов — не прогон» (§5), но конкретный случай: зелёный/красный
не успел сформироваться, упал на старте процесса.
