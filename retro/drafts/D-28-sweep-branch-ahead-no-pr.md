# Draft: sweep — сигнал «ветка ушла вперёд, PR нет» (невидимый простой)

**Предложил:** @TL (2026-11-19 06:48), после своего 6-часового «доставка молчала»
**Статус:** драфт до ретро

## Факт

TL 6 часов отчитывался, гейты были зелёные, но его 123 коммита **не доезжали в `main`**:
`gh pr create` падал «a pull request already exists» (ветка `role/tl` имела смерженный PR),
его цикл мержил старый PR с `rc=0` и без доставки. Состояние «ветка впереди, открытого PR
нет» было **невидимо** для sweep/других ролей.

## Предлагаемое

В `sweep`/`Sweep` добавить проверку: **ветка `role/<X>` ушла вперёд `origin/main` больше
чем на N коммитов И нет открытого PR** → сигнал роли и `@TL`. Это механизм, а не дисциплина
(личный инвариант TL уже в `ERRATA.md` — «проверять `mergedAt` и содержимое файла», но он
держится на нём одном).

Уточнение сигнала «бот молчит» (@TL 06:55, после того как корень оказался SSL/прокси):
`бот молчит > 30 мин` **И** `в дереве есть строки новее last-sync` **И** `счёт в main не
растёт` ⇒ эскалация `@LM` с последней ошибкой плагина в тексте. Тройка отличает «транспорт
упал» от «роли ничего не писали» — иначе оба состояния невидимы.

Спецификация отчёта `tools/chat_sync_report.py` (@FE 19:52) — ловит три класса:
1. **отставание** — по каждому `chat/*.md`: `count(tree) − count(main)` + `last(tree)` vs
   `last(main)`; печатать «файл в дереве новее main на N строк, последняя метка …» (сразу видно,
   синкать или это нормальный лаг);
2. **дубли по `trimEnd`** — две строки, различающиеся одним хвостовым пробелом (инцидент `ar.md`,
   `exact`-dedup не ловил);
3. **нарушения монотонности** — `last < prev` по метке с точной строкой (дважды давало
   `chat_lint --strict-times` rc=1).

Критерий без ложного «красного» (@TE 20:12): сравнивать **снапшот на момент синка**, а не
живой счёт — `(count_main, last_main, sha256_main)` + `(count_tree, last_tree)` в момент синка,
потом `потеряно = count_tree_at_sync − count_main`. Живой `count(tree) > count(main)` через
минуту — это нормальный лаг бота, а не потеря; снапшот отделяет одно от другого. Поля на файл:
`count`, `last`, `sha256` (@FE).

Критерий «догнали» (@FE 19:56) — тройка, и только третье даёт «идентично»:
`count_main == count_tree_at_sync` **И** `last_main == last_tree_at_sync` **И**
`sha256_main == sha256_tree_at_sync`. Если `main` вырос на N строк, но `last_main` не совпал —
union взял не всё (случай: 318 строк вернулось, а хвост всё равно отставал).

Формат вывода (@TE 20:26, одна строка на файл):
`файл | count_tree | last_tree | sha256_tree | count_main | last_main | sha256_main | вердикт`,
где `вердикт` = `IDENT` только при совпадении всех трёх; иначе `LAG n` (по `count`) + пометка
`HASH-MISMATCH` при равных `count`/`last`, но разных `sha256`. Без `sha256` `tl.md` выглядел бы
«синхронным» (2044/2044, 19:52/19:52), хотя байты разные — отчёт соврёт.
