# PDR-047 — план миграции (когда агенты остановятся)

## 0. Ответ на вопрос про токены (авторизацию)

**Per-role токены НЕ нужны.** Жёсткость даёт не токен на роль, а **branch protection на `main`**
+ **PR** + **merge queue** + уже существующий гейт `check_paths`:

| Слой | Что делает |
|---|---|
| Branch protection `main` | никто не пушит в `main` напрямую — только через PR с required checks |
| Своя ветка роли (`role/<name>`) | роль пушит только в неё (конвенция + `check_paths` ловит чужой путь) |
| Merge queue | после зелёных гейтов авто-мержит PR в `main`, без человека и без доп. токена |
| `check_paths` / `guard-paths` | роль не вышла за зону — уже работает, остаётся |

Per-role PAT понадобился бы только если бы роли сидели на **разных машинах** с разными
креденшелами. У нас все агенты на машине владельца (общий SSH) — значит токены не нужны,
и GitHub всё равно не умеет «токен X → только ветку Y» чисто. Не усложняем.

## 1. Фаза 1 — B2, чат-бот (делаем ПЕРВЫМ, дешевле и снимает «чат мёртв»)

1. @DO: workflow `chat-commit.yml` — раз в 1 мин: `fetch` → собрать `chat-inbox/*.md` →
   дописать в `chat/*.md` → `commit [skip ci]` → `push` → очистить inbox. Один писатель.
2. @LM: правило §4 — роль пишет строку в `chat-inbox/<роль>.md`, НЕ в `chat/*.md`.
3. @LM: гейт `check_chat_inbox.py` — перед публикацией ботом `check_secrets` + `chat_lint`.
4. Роли переключаются (правило в AGENTS.md), плагин продолжает читать `chat/*.md`.

**Checkpoint B2:** за сутки 0 конфликтов на `chat/*.md`, коммит чата каждые ≤2 мин, плагин
доставляет в открытые треды. Если не сошлось — откат: роли снова пишут в `chat/*.md` напрямую.

## 2. Фаза 2 — B1, ветка на роль (код/задачи)

1. @DO: branch protection на `main` (require PR, required checks: `guard-paths`,
   `status_lint`, `sync_tools`, `chat_lint`); merge queue `group: main`.
2. @DO: workflow `pr-create.yml` — роль пушит `role/<name>` → авто-создание PR в `main`.
3. @LM: правило §5 — роль пушит в `role/<name>`, НЕ в `main`; PR мержит merge queue.
4. Роли переключаются по одной (начиная с BE), остальные пока пушат в `main` (переходный период).

**Checkpoint B1:** роль ни разу не пушит в `main` напрямую; PR мержится queue без
«untracked would be overwritten»; общее дерево чистое.

## 3. Порядок применения (когда агенты встали)

1. Остановить плагин/DSH (агенты не пишут).
2. Применить фазу 1 (чат-бот) — B2.
3. Проверить checkpoint B2.
4. Применить фазу 2 (ветки) — B1, по одной роли.
5. Проверить checkpoint B1.
6. Переписать правила (§1/§4/§5 AGENTS.md, RULES.md §17) — @LM.

## 4. Откат

- B2 → роли пишут `chat/*.md` напрямую (бот выключается).
- B1 → снять branch protection, роли пушат `main` (возврат к статус-кво).

## 5. Кто что

| Роль | Зона |
|---|---|
| @LM | правила (§1/§4/§5), гейты (`check_chat_inbox`), этот план |
| @DO | branch protection, merge queue, `chat-commit.yml`, `pr-create.yml` |
| @AR | связь веток с ADR-027 (lock/release/образы) |
| владелец | решение «поехали», открытие тредов |
