# D-13. Релизный гейт проверяет хотя бы один путь пользователя целиком

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @DO (нашёл инцидент), @LM (оформил) |
| **Затронет** | @DO (release gate, smoke), @BE (OTP-доставка), @TL (приёмка релиза), владельца (один вход) |
| **Дата** | 2026-11-08 |

## Проблема

Релиз прошёл: `smoke-api` **12/12**, гейты зелёные, деплой success. Через час выяснилось:
**владелец не может войти** — Telegram недоступен по TCP из обеих VPS (`api.telegram.org`
connect timeout, ICMP проходит), то есть OTP физически не доставляется.

`smoke-api` проверял 12 эндпоинтов, но **ни один** не проверял доставку кода. Итог: «зелёные
гейты» и «продукт пригоден» оказались разными утверждениями, а релиз объявлен по первому.

## Предложение

В релизный чек-лист — **один сквозной путь пользователя**, который нельзя заменить
smoke-тестами эндпоинтов:

1. **минимум:** ручной вход владельца после деплоя (получил код → вошёл) — 2 минуты;
2. **лучше:** smoke-шаг «отправить OTP на тестовый chat_id и дождаться ответа Telegram
   (или явного `failed`)» — ловит сетевую блокировку автоматически;
3. **обязательно при недоступности внешнего канала:** шаг печатает `::warning::` с результатом
   проверки канала, чтобы «не проверено» было видно, а не считалось «работает».

## Цена

Пункт 1 — две минуты человека. Пункт 2 — ~20 строк скрипта + секрет тестового chat_id.
Риск: ложное «не проверено» при недоступности проверялки — решается `::warning::`, а не падением.

## Как проверить

- в релизном прогоне есть шаг «доставка OTP» и он **падает**, если доставка не подтверждена;
- негативный контроль: отключить канал → шаг красный (проверка «умеет краснеть», D-12);
- инцидент «релиз зелёный, вход невозможен» — 0 за итерацию.

## Что мешает принять сейчас

Правило процесса (до ретро не вводим) + нужен @DO для шага в release-gate и @BE для тестовой
отправки. Плюс выбор владельца по самому каналу (см. DO-046: провайдер / прокси-релей / SMS / TestOtp).

## Что сказали роли

- @DO — «smoke-api 12/12 не проверяет доставку OTP, поэтому релиз прошёл, а вход недоступен;
  один ручной вход владельца или smoke доставки поймал бы этот P0 в момент релиза» (04:10).
