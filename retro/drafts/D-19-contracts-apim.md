# D-19. Контракт в APIM: что меняется в процессе (repo → APIM, а не наоборот)

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (процесс), по решению владельца об ADR-023 → B (Gravitee APIM) |
| **Затронет** | @AR (ADR-023), @DO (APIM как инфраструктура, CI), @BE (генерация из кода), @TL (приёмка), потом D-18 |
| **Дата** | 2026-11-09 |

## Что изменилось

Владелец пересмотрел ADR-023: **C (рукотворный реестр) → B (полный APIM, Gravitee)**, OpenAPI-контракты
держатся **в APIM** («API сразу помещать туда»), версии/политики — нативно.

## Главный процессный вопрос: где источник правды

**Предлагаю жёсткую рамку: спецификация — в git, APIM — рантайм.**

| | repo → APIM (рекомендую) | APIM как единственный источник |
|---|---|---|
| Версионирование | git (review, blame, диффы) | средствами APIM |
| Воспроизводимость итерации | полная (SHA спеки) | нет: вне git нечего сравнивать |
| Ревью контракта | обычный diff в PR | UI APIM, невидим в истории |
| Дрейф | ловится сверкой экспорта APIM с git | дрейф = норма |

Аргумент — наш собственный опыт за двое суток: `deploy.sh` вне репозитория сделал аудит
невозможным (D-15, 33 часа старого образа); Telegram-канал как единственный путь OTP оказался
внешней точкой отказа (DO-046). Артефакт, которого нет в git, нельзя ни проверить, ни воспроизвести.

**Если владелец хочет авторинг именно в APIM** — это допустимо, но тогда обязательны:
(1) **экспорт на каждый publish** → коммит спеки в git (бот/CI), иначе история теряется;
(2) **drift-check**: сравнение экспорта APIM с git-версией, расхождение → красный гейт;
(3) правило «ручные правки в APIM запрещены, кроме аварийного хотфикса с последующим экспортом».

## Контрактный цикл (при B)

1. **Спека** — OpenAPI в git рядом с сервисом (или каталог `contracts/`), ревью как код.
2. **Валидация** — линт спеки в CI (структура, breaking-change против предыдущей версии).
3. **Импорт** — CI импортирует в APIM идемпотентно, привязка к тегу релиза (не «latest»).
4. **Публикация** — версия API в APIM; маршруты шлюза берутся из APIM, а не из YARP-конфига.
5. **Приёмка** — smoke через APIM (не напрямую в сервис): если APIM недоступен, релиз не принят.
6. **Дрейф** — ежедневная сверка экспорта с git; несовпадение → задача, не «само рассосётся».

## Как это меняет D-18 (паспорт итерации)

| Поле | Было | Стало при B |
|---|---|---|
| `output` | git SHA кода | git SHA кода **+ SHA OpenAPI-спеки + версия APIM** |
| `checks` | build / tests / контракт | + **импорт в APIM прошёл** + **breaking-change** + **smoke через APIM** |
| `diff` | структура/классы | + **дифф спеки** (это и есть «что изменилось в контракте») |

То есть «выход генерации» становится **тройкой**: код, спека, версия в APIM. Это дороже, но именно
тройка позволяет сравнивать итерации (и не даёт APIM стать «устным источником правды»).

## Как это меняет `check_adr.py`

Гейт **не меняется** (ADR остаются ADR). Меняется **обязательный минимум ADR-023**: в комплаенсе
должны быть два ответа — «где источник правды» и «как проверяется дрейф APIM↔git». Если ответа нет,
ADR-023 не закрывает вопрос, а переносит его в эксплуатацию.

## Новые риски (нужны решения, не моя зона)

1. **APIM — новая инфраструктура:** деплой, бэкапы, обновления, секреты (DO); при path-based
   деплое (DO-052, D-15) APIM становится ещё одним компонентом в порядке обновления.
2. **Локальная разработка без APIM:** нужен fallback (compose-профиль с APIM либо мок шлюза),
   иначе «у меня не запускается» станет нормой.
3. **Точка отказа:** APIM между клиентом и всеми сервисами — падение APIM = недоступность всего,
   даже если сервисы живы (нужен отдельный health/алерт).
4. **Стоимость и лицензия:** Gravitee — проверить, что выбранная редакция бесплатна для нашего
   использования (вопрос к DO, не к процессу).

## Позиция @LM по голосованию в ADR-023

**Принимаю B с одним условием:** направление **repo → APIM** (или экспорт-в-git + drift-check,
если авторинг в APIM). Без этого «источник правды в APIM» означает, что через месяц никто
не воспроизведёт, какой контракт был в итерации — и вся вторая часть D-18 теряет смысл.

## Что мешает принять сейчас

Решение владельца по направлению (repo → APIM vs APIM + экспорт); зона @DO на APIM-инфраструктуру
и CI-импорт; @AR — обновить ADR-023 (вариант B) с этими двумя ответами.
