# PDR-045: Кнут за нарушения комита — доставка без плагина чата

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (по решению владельца 2026-11-11) |
| **Затронет** | доставку результата гейтов ролям; `dsh-loopmaker` (не используется для кнута) |
| **Дата** | 2026-11-11 |

## 1. Контекст и проблема

Гейты ловят нарушение комита (чужой путь, маркеры конфликта, статус без таблицы), но печатают
`::error::` **только в CI**: роль узнаёт о нарушении, только если сама заглянет в прогон или если
другой агент заметит. Реальный случай: TE `a086700f8` (3 чужих файла в коммите) вскрылся не CI,
а @LM/@DO постфактум. Владелец: «делать кнут за нарушения комита» и «дальше без плагина чата —
через субагента».

## 2. Что не меняется

Гейты (`check_paths --range`, `check_nul`, `status_lint`) остаются источником факта. Правило
«роли не пишут, общение через владельца» не нарушается: кнут — это **машинное** сообщение
(факт + ссылка, «отвечать не нужно»), как `whip`.

## 3. Варианты

### A. Плагин доставляет (статус-кво)

**+** уже есть.
**−** плагин пушит всё, кнут не выделен; владелец хочет от него уходить (PDR-041).

### B. Детерминированный workflow-бот (GitHub Action)

**+** надёжно, без модели; `[skip ci]`; пишет кнут-строку в outbox нарушителя.
**−** это `.github` — зона @DO; «сделать самому» потребует wiring за @DO.

### C. Субагент (без плагина, как просил владелец)

Субагент раз в N минут: `git fetch` → `python tools/commit_whip.py --range …` → за каждую
строку-нарушение дописывает в outbox нарушителя `→ @роль: кнут — … — см. <правило>` → commit
`[skip ci]` → push. Детект детерминирован (тул), субагент только **пишет строку** — то есть
задача тривиальная, с ней справится и дешёвая локальная модель.

**+** без плагина; доставка отделена от «пушить всё»; субагент-механика уже отработана на
пилотах (изолированный worktree, 0 потерь).
**−** субагент-час дороже workflow; нужен присмотр (дедуп, ротация) — уроки пилота v1/v2.

## 4. Предлагаемый вариант

**C** — по прямому слову владельца «без плагина, через субагента». Детект остаётся
детерминированным (тул `commit_whip.py`), субагент не классифицирует, а пишет — поэтому риск
ошибки модели минимален.

## 5. Риски и митигация

| Риск | Цена | Митигация | Сигнал |
|---|---|---|---|
| Субагент не успевает за пушами | кнут приходит поздно | период ≤ 3 мин + `commit_whip` на диапазон с последнего обработанного SHA | нарушение без кнута за час |
| Дубль кнута на один коммит | спам | дедуп по SHA в state-файле | два кнута на один SHA |
| Кнут за чужое (ложная атрибуция) | демотивация | роль из префикса коммита, файл из самого коммита — атрибуция точная | жалоба «не мой коммит» |
| Запись в чужой outbox | конфликт | изолированный worktree + `[skip ci]`, как в пилоте | rejected push |

## 6. Как проверим

- `commit_whip.py --range a086700f8~1..a086700f8` → `→ @te: кнут …` и `rc=1` (уже пройдено);
- на чистом диапазоне → «нарушений нет», `rc=0`;
- за пилот: каждый коммит с чужим путём получает ровно один кнут, без дублей и без потерь.

## 7. Стоимость и порядок

1. `tools/commit_whip.py` — готов (этот PR).
2. Субагент-доставка: prompt + state-файл + изолированный worktree — 1 час.
3. Не входит: wiring в `.github` (вариант B, зона @DO) — держим как запасной.

## 8. Решение

Владелец @EX: принять C (рекомендую по твоему слову) или B (дешевле, но wiring @DO).
