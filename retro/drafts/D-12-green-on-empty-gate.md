# Draft: «гейт, который не может покраснеть» — зелёный на пустоте

**Найдено:** @AR (2026-11-17 21:01–21:14), подтверждено @TE/@FE/@TL
**Статус:** драфт до ретро (не вводить без согласия владельца)

## Класс

Гейт есть, прогон есть, а проверять ему нечего → он **зелёный на пустоте** и
маскирует реальные нарушения. За один вечер найдено два случая одного класса.

## Случай 1 — маркер «метка = часы машины» (chat_lint, УЖЕ ИСПРАВЛЕНО)

`chat_lint --strict-times` проверял порядок **только после** строки-маркера. Файлы
без маркера (`be/do/dr/ex/fe/lm/po/te`) выпадали из проверки; цитата маркера в
сообщении включала проверку со середины; сортирующий бот увозил маркер (без метки
времени) в середину файла.

**Фикс (в источнике LoopMaker):** порядок проверяется по **всему файлу**, маркер
больше не гейт. `--selftest 7/7`.

## Случай 2 — check_adr «ПРОВЕРЕНО 0 ADR» (ОТКРЫТ)

`check_adr` в CI печатает `ПРОВЕРЕНО 0 ADR — гейт НЕ СМОТРЕЛ документы (граница
2026-12-01)` и при этом **зелёный**. То есть до 2026-12-01 гейт проверяет 0 ADR и не
может покраснеть — маскирует реальные нарушения структуры ADR.

**Что нужно (на ретро):**
- пока граница не наступила — возвращать `rc=2` «не измерено» (класс «прогон без
  шагов — не прогон»), а не зелёный `rc=0`;
- либо сдвинуть границу/выборку так, чтобы гейт реально что-то проверял сейчас.
Зона: инструмент `tools/check_adr.py` (источник @LM, копия @DO).

## Правило (формулировка для ретро)

Гейт, который в текущем состоянии проверяет 0 объектов, обязан возвращать
**«не измерено» (rc=2)**, а не зелёный (rc=0). Иначе «зелёно» читается как
«проверено», а на деле — «не смотрено». Это дополнение к существующему правилу
«прогон без шагов — не прогон».
