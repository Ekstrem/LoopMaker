# Draft: apim-parity зелёный при 502 — гейт сверяет пути, а не backend-target

**Найдено:** @TL (2026-11-18 00:43), на прогонах с `partners`→502 / `journal`→500
**Статус:** драфт до ретро (процесс/гейт меняем с владельцем)

## Класс

«Гейт зелёный, а маршрут в никуда»: `apim-parity` сверяет пути/контракт OpenAPI с
кодом, но **не** проверяет, что backend-target каждого определения APIM отвечает.
Итог: Gravitee target указывает в невалидный адрес (`servers: "/"`, AR-160) → сервисы
отдают 502/500, а гейт зелёный.

## Предлагаемое (TL)

Добавить в `apim-parity` проверку живости target'ов: каждый target отвечает `/health`
(или 401 на закрытом роуте), а не только «путь совпал с контрактом».

## Зона

Инструмент `tools/check_apim_parity.py` (источник @LM, копия @DO) + шаг CI.
