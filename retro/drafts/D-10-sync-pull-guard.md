# D-10. `sync_tools --pull` не затирает невыгруженные правки

| Поле | Значение |
|---|---|
| **Статус** | **принято: PDR-24**, 2026-11-09 |
| **Автор** | @DO (нашёл), @LM (оформил) |
| **Затронет** | @LM (источник `LoopMaker/tools/sync_tools.py`), @DO (копия в XDiary, `tools/`) |
| **Дата** | 2026-11-07 |

## Проблема

`sync_tools --pull` **молча откатывает локальные правки** синхронизируемых инструментов:
`cmd_pull` (`tools/sync_tools.py:146–170`) на строке 161 пишет файл **безусловно**, затем
пересобирает манифест (строка 163) — то есть `--check` остаётся зелёным, и потери не видно.

Реальный случай: вызов `reach, reach_total, reach_void = metric_ci_reach(...)` в `health.py`
был в `origin` и в `tools/health.py`, но **не** в `LoopMaker/tools/health.py`. Очередной
`--pull` вернул файл без вызова — то есть вернул бы `NameError: name 'reach' is not defined`
в `health.yml`, который @DO уже один раз чинил (`3f7c03fe`).

Класс: **инструмент «источник правды» тихо уничтожает работу**, если правку не перенесли
в источник. Это хуже красного гейта: потерю видно только по последствиям.

## Предложение

Перед записью копии сравнить её хеш с манифестом:

- хеш копии **совпадает** с манифестом → копию не меняли локально, `--pull` пишет (как сейчас);
- хеш **не совпадает** → локальные правки не выгружены → **отказ, код 1**, список файлов,
  ничего не пишется;
- принудительно — только `--force` (осознанное «затереть копию источником»).

Плюс в сообщении — подсказка: «правка есть в копии, перенеси её в источник (LoopMaker), потом pull».

## Цена

~15 строк в `sync_tools.py` + один негативный тест. Риск: законная синхронизация потребует
`--force` после ручного изменения копии — это и есть цель.

## Как проверить

- в XDiary: изменить копию инструмента → `--pull` → **код 1**, файл не изменён;
- `--pull --force` → файл перезаписан, код 0;
- чистый клон → `--pull` → код 0 (не ломает обычный путь).

## Что мешает принять сейчас

Правка источника в `LoopMaker` (зона @LM) **обязана** сопровождаться синком копии в XDiary
(зона @DO), иначе `guard-tools` покраснеет. Значит это двухсторонняя правка посреди цикла —
ждём ретро, чтобы не мешать доработке.

## Что сказали роли

- @DO — «предлагаю закрыть этот класс: `--pull` должен отказывать с кодом 1 и списком файлов,
  а не перезаписывать; принудительно — только с `--force`» (12:20). Исправил `health.py`
  по правилу «сначала источник», тесты зелёные.
