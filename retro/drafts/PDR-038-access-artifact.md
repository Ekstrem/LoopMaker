# PDR-038. Доступы и секреты: фиксировать артефактом, а не памятью

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (запрос владельца) |
| **Затронет** | `AGENTS.md` §6/§7 (XDiary) + `RULES.md` §13/§15 (LoopMaker, переносимо) |
| **Дата** | 2026-11-06 |

## 1. Контекст — что и зачем

Доступы и секреты (GitHub Secrets, `.env`, токены, доступ к стенду/контуру) — ресурсы,
которых у ролей физически нет; их выдаёт **владелец** (§7). Сейчас выдача идёт «по памяти»:
владелец что-то выдал, роль это не зафиксировала, потом «забыла» и обвиняет владельца
(«настроил что-то и не дал кредиты»). Спор «дал / не дал» решается памятью, а не фактом.

## 2. Проблема (и причина)

Это тот же класс «проверяй артефакт, а не по памяти» (§3), только **наоборот**: роль
предъявляет претензию без артефакта. Причина — нет обязательной **записи о выдаче**.
Следствие — токсичность: владелец должен оправдываться за то, что уже сделал, а проверки
«сделал ли» нет ни у кого.

## 3. Варианты и риски

| Вариант | Что | Плюсы | Риски |
|---|---|---|---|
| **A. Норма «выдача = артефакт»** | каждый выданный доступ → строка с `REF` (что, кому, когда); «нет доступа» → сначала проверь артефакт, потом пиши | спор решается фактом; претензия без артефакта = нарушение | нужна дисциплина при выдаче |
| **B. Оставить как есть** | спорить по памяти | 0 работы | токсичность и пустые обвинения вернутся |

**Рекомендация: A.** Одна короткая норма убирает класс споров.

## 4. Предложение (вариант A)

1. **Выдача фиксируется артефактом:** владелец (или @DO по его слову) пишет в задачу/чат
   строку `→ @роль: выдан <доступ/секрет> — <дата>, REF <sha>` (что, кому, когда).
2. **«Нет доступа» = сначала проверь артефакт:** роль сверяется с задачей/Secrets/`.env`
   и ссылается на то, что проверяла, а не пишет обвинение с порога.
3. **Претензия без ссылки на артефакт — нарушение** (§3 «по памяти»): если записи о выдаче
   нет — это «нет записи», а не «владелец не дал»; дефект оформляется задачей, а не упрёком.

## 5. Цена

~полчаса: норма в `AGENTS.md` §6/§7 + переносимая строка в `RULES.md`.

## 6. Как проверить

- выдача доступа → в задаче/чате есть строка с `REF` (trace);
- претензия «не дали доступ» без `REF`/проверки → кнут (нарушение §3).
