# PDR-047: Отказ от общего дерева — ветка на роль (код) + чат через бота-единственного писателя

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM (по решению владельца 2026-11-12 «в конце итерации что-то с этим надо сделать») |
| **Затронет** | git-модель (ветки/MR/PR), чат (`5-tech-backlog/chat/`), `dsh-loopmaker`, CI-воркфлоу |
| **Дата** | 2026-11-12 |

## 1. Контекст и проблема

Общее дерево — корень большинства затыков итерации. Замеры этой итерации:

| Факт | Значение |
|---|---|
| Локальный чекаут отстал от `origin` | **102 коммита** (плагин читает его и «не видит» свежий чат) |
| Синк дерева блокируется чужими untracked-файлами | «untracked would be overwritten» (`9-tests/*` @TE) |
| Смытые правки (роли за сутки) | ≥5 файлов (@TE: `accept_read_path`, `PROBE_TIMEOUT`, …) |
| Сообщений сгорело по TTL в плагине | **15 738** |
| Конфликтов на общих файлах (`README.md`, чат) | регулярно, каждый день |

Причина одна: **роли пишут в одну и ту же рабочую папку**, поэтому чужая незакоммиченная
работа блокирует чужой `merge`, чужие `checkout`/`reset` смывают правки, а плагин читает
устаревшую локальную копию.

## 2. Что не меняется

Модель петли: задача = файл, чат = outbox-строки, координатор проверяет, владелец закрывает.
Формат чата (`- [ts] → @роль: текст`), гейты (`guard-paths`, `status_lint`, `sync_tools`,
`chat_lint`), правило «пуш ≠ пробуждение». Плагин `dsh-loopmaker` остаётся доставщиком.

## 3. Варианты

### A. Статус-кво (общее дерево, все пушат в `main`)

**+** ничего не менять; чат доезжает мгновенно (прямой пуш).
**−** доказано: 102 отставания, смывы, блокировки, «чат мёртв». Держится на дисциплине,
которая не работает под нагрузкой.

### B. Разделить потоки (рекомендую)

**B1. Код/задачи — ветка на роль + PR + required checks + merge queue.**
Каждая роль работает в **своей ветке** (`role/<name>`), мерж в `main` — через GitHub PR
с обязательными гейтами и **merge queue** (очередь перетестирует PR на свежем `main`
и сливает атомарно — гонок на merge нет).

**B2. Чат — «нейтральная» директория, единственный писатель — бот.**
Роли **не пушат** в `5-tech-backlog/chat/*.md` напрямую. Каждая роль пишет строку чата в
свой **staging** (например `chat-inbox/<роль>.md` или свой файл-в-ветке), а бот-коммиттер
**раз в минуту** собирает все pending-строки и публикует их в `chat/*.md` одним коммитом.
Итог: у чата один писатель (бот) → конфликтов на чате нет по построению; плагин всегда
читает свежий `main`.

**+** устраняет корень (нет общей папки для записи); чат остаётся быстрым (≤1 мин); PR
даёт ревью и гейты на коде; merge queue убирает гонки.
**−** два механизма вместо одного; +1 мин латентность чата; нужна настройка branch
protection + merge queue (@DO) и staging-бота.

### C. Всё через PR, включая чат

**+** единообразно.
**−** чат-строка «→ @X: блокер» едет через ветку→PR→ревью→merge = минуты-часы. Для
сердцебиения петли это смерть. Отброшен.

### D. Чат через чтение `origin` напрямую (без бота)

Плагин читает `git show origin/main:…`, а не локальную папку. Роли по-прежнему пушат в `main`.

**+** минимум изменений (правка плагина), чат мгновенный.
**−** не решает смывы и блокировки на общем дереве (только «плагин видит свежее»); это
частный фикс, а не устранение причины.

## 4. Предлагаемый вариант

**B** (B1 код + B2 чат). A доказанно ломается; C убивает чат; D лечит симптом, не причину.
B устраняет общую папку записи целиком: код — через изолированные ветки, чат — через
единственного писателя-бота.

## 5. Риски и митигация

| Риск | Цена | Митигация | Сигнал |
|---|---|---|---|
| Бот-коммиттер падает — чат встал | тишина в чате | бот в GitHub Actions + health-чек; падение логируется | нет коммита чата >2 мин |
| Бот-коммиттер конфликтует сам с собой | rejected push | один писатель + fetch/merge/retry в боте | ≥3 rejected подряд |
| Staging-файл роли расходится с опубликованным | дубль/потеря строки | бот после публикации очищает staging; дедуп по хешу строки | строка появилась дважды |
| PR-задержка на коде | задача «висит» | merge queue авто-мержит после гейтов, без ручного approve (кроме критичного) | PR висит > N без решения |
| Секрет в staging (публичный repo) | утечка | `check_secrets` на staging перед публикацией ботом | — |
| Переход ломает текущие worktree ролей | простой | поэтапно: сначала B2 (чат-бот), потом B1 (ветки) | роли не могут пушить |

## 6. Как проверим

- За итерацию после B2: **0** конфликтов на `chat/*.md`; коммит чата — **каждые ≤2 мин**;
  плагин доставляет в открытые треды (не 0, как сейчас).
- После B1: роль ни разу не пушит в `main` напрямую; PR мержится через queue без
  «untracked would be overwritten»; `git status` общего дерева чистый.
- Латентность чата: строка роли → опубликована ботом → ≤ 90 сек.
