## Находка

У ролей есть **свои git worktree**: в главном `XDiary` — `main`, плюс `xd-fix41…46`, `xd-cnt2` (temp,
detached HEAD). Поэтому §5 «дерево у всех ролей одно» **неточно**:
- правки в чужом worktree не видны в главном, `git merge` в главном на них не реагирует;
- зато в том worktree возникает `untracked would be overwritten`, который выглядит как общий блокер;
- часть «потерянных строк» сегодня — правки, сделанные в разных worktree, а не «снесло общим деревом».

## Предложение (на ретро → PDR)

В §5.3: «диагностика merge-блокера начинается с `git worktree list` + `git status` **в нужном worktree**;
чужой worktree не правим, лечим локально (`rm`/`stash -u`)». Плюс поправить §3/§5.5, где «дерево одно»
встречается как причина.

**Уточнение @TE (16:12):** `git worktree list` показывает и **мёртвые записи** (`… prunable`, путь в `%TEMP%`
уже удалён) — диагностика по одному `git worktree list` может увести на несуществующее дерево. Формулировка:
«prunable-записи игнорируем; `git worktree prune` выполняет владелец, не в общем дереве». Отсекает два случая:
не тот worktree и мёртвая запись.

## Почему не вписываю сразу

Владелец (2026-11-12): правила меняются **на ретро по результатам PDR**, кроме критов, обсуждённых
с владельцем. Это — уточнение неточной нормы, не крит → драфт, PDR на ретро.
